# MediBrief Clinical Hazard Register

This register is a living engineering and product-risk document. It does not itself establish regulatory compliance. Every clinical or patient-specific feature change must review the hazards below and add new hazards when applicable.

## Risk-control rules

1. A disabled feature is a valid risk control only while no reachable code path or product claim implies that the feature is active.
2. A disclaimer alone is not an adequate control for a hazardous automated function.
3. A source citation or evidence identifier does not prove semantic correctness.
4. “Human in the loop” is not a complete control without clear review state, source visibility, correction support, and usability evidence.
5. Third-party privacy settings must be enforced programmatically where possible and rechecked for policy drift.
6. Every release must review new data flows, new model/provider IDs, new rule outputs, new user actions, and changed terminology mappings.
